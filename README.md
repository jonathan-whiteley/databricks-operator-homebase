# Lakehouse Market · Homebase

**A Databricks App built end-to-end on the lakehouse: store-manager daily operations console for a fictional QSR.**

Five tabs (Labor, Loyalty, Supply Chain, Sentiment, Predictive Maintenance), one synthetic dataset, real Databricks Lakebase write-back, real Model Serving, and a Genie panel embedded on every tab. Designed for the Data + AI Summit demo loop and SA-led customer walkthroughs.

> Working name: `lakehouse-market-e2e-DAIS-demo` · Product name in the UI: **Lakehouse Market · Homebase**

---

## Who it's for

The user inside the app is a **single-store QSR manager** logging in at 7am to run their shift:

- Lock today's schedule (Labor)
- Push counter prompts and recover at-risk regulars (Loyalty)
- Release reorders before close and prep for tomorrow's deliveries (Supply Chain)
- Triage new reviews and respond (Sentiment)
- Schedule a tech before the fryer dies (Predictive Maintenance)

The audience watching the demo is a Databricks customer's ops or platform team: "this is what your store manager's console looks like when you build it on the lakehouse."

## Architecture at a glance

```
                ┌──────────────────────────────────────┐
                │   React 19 + Vite + Tailwind 4 UI    │
                │   Hub + 5 tabs · GenieChat on each   │
                └────────────────┬─────────────────────┘
                                 │  /api/*
                ┌────────────────▼─────────────────────┐
                │   FastAPI (uvicorn on port 8000)     │
                │   routers: meta · labor · loyalty    │
                │            supply · sentiment        │
                │            maintenance · genie       │
                └─┬────────────┬───────────────┬───────┘
                  │            │               │
                  ▼            ▼               ▼
            ┌──────────┐ ┌───────────┐ ┌──────────────┐
            │ UC reads │ │  Lakebase │ │  Genie space │
            │ via SQL  │ │  Postgres │ │  + Model     │
            │ Warehouse│ │  (writes) │ │  Serving FM  │
            └──────────┘ └───────────┘ └──────────────┘
```

- **UC (read-only)**: `${catalog}.lakehouse_market.*` — 21 tables across the 5 domains, generated by the init job.
- **Lakebase (read/write)**: 5 app tables for manager actions (`app_labor_overrides`, `app_offer_pushes`, `app_purchase_orders`, `app_review_responses`, `app_work_orders`).
- **Model Serving**: one custom endpoint, `lhm-labor-recommender`. Churn, CLV, and RUL scores are precomputed at data-gen time.
- **Foundation Models**: `databricks-claude-sonnet-4-6` for the weekly sentiment digest. `databricks-meta-llama-3-3-70b-instruct` for batch review labeling.
- **Genie**: one shared space (`lhm-ops-assistant`) embedded on every tab via the `GenieChat` component, with tab-scoped prompt chips and a hidden store-id context blurb.

## Quick start — deploy to Databricks

Prereqs: `uv`, `node` ≥ 20, `databricks` CLI v0.230+, authenticated to the target workspace (default profile `DEFAULT` pointing at `fe-vm-jdub-vm-serverless`).

```bash
make install      # uv sync + npm install
make validate     # databricks bundle validate
make deploy       # builds UI, then `databricks bundle deploy`
make run-init     # runs the 5-task init job (data gen + ML)
```

**First-time-only manual step:** create the Genie space.

1. In the workspace UI, create a Genie space named `lhm-ops-assistant` scoped to all 21 tables in `${catalog}.lakehouse_market` (full list in the spec §8).
2. Add curated example questions prefixed `Labor: …`, `Loyalty: …`, etc.
3. Copy the space id (UUID) and set it on the app:
   ```bash
   databricks apps set-env lakehouse-market-homebase --env GENIE_SPACE_ID=<uuid>
   ```
4. Re-deploy: `make deploy`.

Open the app from the workspace UI's Apps page. The hub page loads at `/`.

## Local dev

```bash
make install
cp .env.example .env       # edit with your DATABRICKS_HOST, WAREHOUSE_ID, TOKEN
make dev                   # API on :8000, UI on :5173, /api/* proxied
```

The Vite dev server (`:5173`) proxies `/api/*` to FastAPI (`:8000`). The UI hot-reloads on save.

Required env vars for local dev:

| Var | What | Where to get it |
|---|---|---|
| `DATABRICKS_HOST` | `https://<your-workspace>.cloud.databricks.com` | Workspace URL |
| `DATABRICKS_WAREHOUSE_ID` | SQL warehouse id | Workspace → SQL → Warehouses |
| `DATABRICKS_TOKEN` | PAT | Workspace → Settings → Developer |
| `LAKEBASE_HOST` / `_DB` / `_USER` / `_PASSWORD` | Postgres conn info | DAB output after first deploy |
| `GENIE_SPACE_ID` | Genie space UUID | Workspace → Genie (after manual create) |

Run tests:

```bash
make test
```

## Tab tour

Each tab follows the same skeleton: KPI strip → action queue → secondary detail → embedded `GenieChat` panel → at least one Lakebase write action.

| # | Tab | Action queue | Write-back |
|---|---|---|---|
| 01 | **Labor** | Day-part cards (Breakfast / Lunch / Dinner / Late) with forecast + recommended headcount + override + lock | `app_labor_overrides` |
| 02 | **Loyalty** | At-risk member queue + counter-prompt picker + **trade-area map** centered on the store | `app_offer_pushes` |
| 03 | **Supply Chain** | Reorder queue (one-click Release PO) + tomorrow's deliveries | `app_purchase_orders` |
| 04 | **Sentiment** | Review inbox with Respond / Flag / Resolve + FM-generated weekly digest | `app_review_responses` |
| 05 | **Maintenance** | At-risk equipment queue (RUL + health ring) + telemetry sparklines + schedule tech | `app_work_orders` |

The **Hub** page (`/`) is the morning briefing: a 5-app circular diagram with badge counts pulled live from the action queues, plus a unified "Today at your store" cross-tab list of the highest-priority items.

## How the AI surfaces work

**Genie (every tab).** Each tab renders a `<GenieChat tabId="…" chips={[…]} />`. The component:
1. Renders tab-scoped prompt chips so the manager can click rather than type.
2. POSTs to `/api/genie/ask` with `{ tab_id, store_id, question }`.
3. The backend prepends a context blurb (`Context: tab=Labor, store_id=42. Scope answers to this store unless asked otherwise.`) before calling the Genie space.
4. Responses stream back into the chat scroll.

**Foundation models (Sentiment tab).** The `/api/sentiment/digest?store_id=…` endpoint pulls 30 recent reviews for the store and asks `databricks-claude-sonnet-4-6` for a 3-sentence summary. Cached server-side for 1 hour per store.

**Model Serving (Labor tab).** The `Recompute` button on a day-part card posts to `/api/labor/recommend` which invokes the `lhm-labor-recommender` Model Serving endpoint with the manager's override revenue.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| App boots but `/api/stores` returns 500 | `DATABRICKS_HOST` or `WAREHOUSE_ID` not set | Check the app env in the workspace; restart |
| Buttons "Lock", "Release PO", etc. show toast but no row appears | Lakebase not provisioned or `LAKEBASE_*` env unset | `databricks bundle deploy` and confirm the instance is running; set env on the app |
| Genie chat says "(no answer)" or errors | `GENIE_SPACE_ID` not set on the app | See "First-time-only manual step" above |
| Map renders gray with no dots | `/api/loyalty/map` returns empty | The init job hasn't run; `make run-init` |
| Recompute button hangs | Labor serving endpoint cold | First call wakes it; subsequent calls are fast (~200ms) |
| `dbldatagen` import fails in notebook | Cluster missing the lib | The notebook installs it via `%pip` at the top; restart the kernel |

## What's intentionally not here

- **Real PII.** All data is synthetic.
- **Auth.** Uses the default Databricks Apps OBO model; no user system.
- **Mobile.** Desktop-only layout.
- **Multi-brand theming in the UI.** The theme-object seam is preserved (`ui/src/lib/themes/lakehouse-market.ts`) but only one brand ships.
- **Production ML quality.** Models are demo-grade; the demo is about the platform integration, not lift over baseline.
